# Повторение в Kaggle

Приватный `criocat/tlab-task1-reproduction` version 1 завершён. Основное
сравнение manual/auto использует тот же код, sample, временные границы,
кандидатов и seed 42/43/44. CatBoost выполняется на **CPU Kaggle**;
запрошенный GPU предназначен для Qwen proposer, а не для обучения бустинга.

Все показанные test-метрики CatBoost повторили локальные результаты:
manual NDCG@10 mean 0,461065, auto-selected 0,464169, popularity 0,433067.
Validation снова выбрала все дополнительные окна. Утверждение о небольшом,
статистически неубедительном приросте остаётся тем же.

CatBoost 1.2.10 совпадает с локальной версией, NumPy/pandas отличаются:
2.1.3/2.3.3 на Kaggle против 2.5.4/3.1.0 локально. Основной pipeline на Kaggle
занял 720,80 с против 330,25 с локально; это CPU разных машин и условия кеша,
поэтому GPU-ускорением CatBoost такой запуск не называется. Peak RSS Kaggle
4 430 868 KiB. Конкретные параметры и аудиты находятся в скачанном protocol.json.

Version 1 использует первоначальный strict-RPN интерфейс LLM-поиск. На Tesla T4
он также дал **0 принятых LLM-кандидатов из 48 попыток**. Поэтому итоговая LLM
политика признаков совпадает с manual: NDCG 0,458863 для seed 42. Random search
принял 12/12 кандидатов и выбрал одно выражение, NDCG 0,461318; его парная
прибавка +0,002455 имеет CI [-0,001611; 0,006551]. Эти числа совпали с отдельным
strict-RPN CPU-запуском. Подтверждено ограничение интерфейса, а не преимущество
LLM над случайным поиском.

LLM-поиск-ветка Kaggle заняла 1207,28 с, весь notebook после запуска — около
1957,59 с (включая другие стадии и установку/загрузку). Устройство подтверждено
строкой `CUDA True Tesla T4`. GPU сам по себе не исправляет несоблюдение формата
маленькой instruction-моделью.

## Отдельное infix-повторение

`criocat/tlab-task1-promptfe-infix` version 1 также завершён на Tesla T4.
Полные таблицы находятся в [GPU_INFIX_RESULTS.md](GPU_INFIX_RESULTS.md).
Qwen приняла 12 кандидатов из 43 попыток; один ответ оказался дубликатом.
Validation выбрала три новых признака. Test NDCG@10 LLM = **0,464049**,
manual = 0,458863, random = 0,461318. LLM-manual delta +0,005186, CI
[0,000588; 0,009536]; LLM-random +0,002730, CI [-0,001821; 0,007164].

Один этот proposal set даёт положительный CI против manual, однако преимущество
перед random не установлено. На CPU LLM-random delta была отрицательной, также
с CI через ноль. Модель и seed номинально те же, но Qwen на GPU использует fp16,
на CPU fp32; sampling/RNG и предложения отличаются. Это отдельная реализация
стохастического поиска, а не побитное воспроизведение CPU-ответов. Основной
CPU-результат не заменялся более удачным GPU; пользовательские выборки одни
и те же и не считаются независимыми при статистическом обобщении.

77 входных признаков LLM-классификатора дают близкий point estimate к
186 признакам generated-all seed 42 (0,464198). Это интересная компактность
итогового классификатора, но ни равенство качества, ни end-to-end экономия памяти
не доказаны: исходная общая матрица в эксперименте всё равно материализовала
все окна. Нужны дополнительные proposal seeds и временные окна.

LLM-поиск run занимает 2217,38 с; весь notebook — около 3004,75 с. CatBoost
выполняется на CPU, GPU ускоряет только LLM. Все три сохранённые GPU-модели
повторно предсказали test с исходными Kaggle-матрицами и воспроизвели метрики;
проверка записана в `artifacts/promptfe_gpu_rescore.json`.
