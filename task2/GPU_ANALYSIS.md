# Независимый запуск кода на Kaggle GPU

Приватный notebook `criocat/tlab-task2-reproduction`, version 1, завершился
успешно. В логе зафиксировано `CUDA True Tesla T4` и `COMPLETED`. Его результаты
сохранены отдельно в [GPU_RESULTS.md](GPU_RESULTS.md), исходные артефакты —
`artifacts/kaggle/task2/tlab/artifacts/task2/`. CPU-таблицы не заменялись.

Все массивы train/validation/test (`x`, `y`, reward, return mask, user, date)
совпали поэлементно с локальным запуском, включая пропуски reward. Проверка записана
в `artifacts/cpu_gpu_data_identity.json`. Исходники фактически отправленной
версии зафиксированы в `kaggle/task2/source_manifest.json` и в скачанном output.
Позднейшие изменения отчётности и infix-интерфейса task1 не относятся к этому
запуску; задача 2 и данные в нём не менялись.

| Политика | Test NDCG@10 | Recall@10 | Predicted watch@10 |
| --- | --- | --- | --- |
| SFT | 0.09337 | 0.1645 | 0.50955 |
| RL без ограничений | 0.09124 | 0.1565 | 0.58758 |
| RL KL=.1 | 0.09275 | 0.1600 | 0.53977 |
| RL KL=1 | 0.09343 | 0.1630 | 0.52765 |
| Balanced five-step | 0.09145 | 0.1565 | 0.54441 |
| Return five-step | 0.09177 | 0.1610 | 0.52902 |
| Continued SFT control | 0.09324 | 0.1615 | 0.50358 |

Validation опять выбрала balanced five-step. Его proxy вырос на 6,84%,
NDCG точечно снизился на 2,05%; парная разница NDCG -0,00192 с CI
[-0,00520; 0,00144]. Неограниченный RL повысил proxy на 15,31%, при этом
один объект появляется в top-10 у 98,25% пользователей против 81,90% у SFT.
Основной качественный вывод воспроизводится: learned reward оптимизируется,
но улучшение релевантности не установлено, концентрация усиливается.

RM: test MAE 0,33591, R² 0,0107. Выигрыш MAE относительно сглаженного item mean
0,00899, CI [0,00516; 0,01310]. Слабость модели отклика сохраняется на GPU.

SFT занимает 41,74 с на T4 против 318,82 с на CPU (примерно 7,6 раза быстрее).
Весь основной pipeline занимает 239,85 с против 506,22 с; подготовка данных
на Kaggle медленнее и занимает 161,69 с. В эти числа не включены установка
пакетов, загрузка данных и отдельный continued-SFT control. Peak CUDA allocation
171 382 272 байта — это PyTorch tensor allocation, а не вся занятая GPU память.

Сравнение всего pipeline также зависит от кеша: локальный user sample уже
существовал, на Kaggle создавался заново. Версии отличаются: CPU Torch
2.14.1+cpu / NumPy 2.5.4 / pandas 3.1.0; GPU Torch 2.11.0+cu128 / NumPy 2.1.3 /
pandas 2.3.3. Поэтому времена отражают реальные два окружения, а не строго
изолированный эффект замены CPU на GPU при идентичных библиотеках и кеше.

Это проверка переносимости вычислений на тех же пользователях, а не новый
независимый статистический эксперимент. Небольшие различия CPU/GPU ожидаемы
из-за арифметики и реализации операций; совпадение seed не означает побитного
совпадения обученных весов. Лучший test-результат между устройствами не выбирался.
