# Окружение и данные

Все команды выполняются из корня этого репозитория. Исходное CPU-окружение:
Python 3.12.3; зависимости экспериментов закреплены в `requirements.txt`,
полный состав исходного окружения сохранён в [environment.json](../result_artifacts/environment.json). Для численного повторения предпочтительно то же
окружение; CUDA-результаты в отчётах приведены отдельно от CPU.

## Установка для обучения на CPU

```sh
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
export PYTHONHASHSEED=42
export CUDA_VISIBLE_DEVICES=""
```

Единый файл requirements.txt закрепляет зависимости экспериментов,
включая CPU Torch. Версии GPU-окружения указаны в инструкциях каждого задания. Локальная LLM для replay не требуется;
для новой генерации используется `shared.download_proposer`.

## Данные

```sh
python -m shared.download
```

Загружается `data_original.zip` из публичного KION. Загрузчик проверяет SHA-256
архива и полноту CSV: 5 476 251 взаимодействие, 962 179 пользователей.
Отдельный upstream `interactions.csv.zip` усечён и не используется.
Из 50 000 равномерно выбранных пользователей сохраняются все 285 343 строки
их доступной истории. Sampling seed — 42; manifests приложены в `data/`.

Повторно загружать уже проверенные файлы загрузчик не будет. Потребуются сеть
и место для данных, feature matrices и checkpoints. Основные CPU-запуски
укладывались примерно в 5 GiB RSS; полнокаталожные дополнения достигали около
9 GiB. Большие matrices и веса игнорируются Git.

## Воспроизводимость

- Основной seed — 42; CatBoost, NumPy и Torch получают зафиксированные seeds.
- `reproduce.py` задаёт `PYTHONHASHSEED=42` всем дочерним процессам.
- По умолчанию `reproduce.py` выбирает CPU. `--device auto` разрешает CUDA;
  его результаты следует сравнивать с соответствующим GPU-протоколом.
- Даты split, выбранные конфигурации и версии записываются в `protocol.json`.
- Для LLM-поиска используются фиксированные `replay/feature_search_cpu.json`;
  это сохраняет и random expressions, и ответы LLM.
- Файлы результатов, протоколов и весов создаются при запуске в `artifacts/`.
  Этот каталог игнорируется Git.

Исходный train/validation/test — временные интервалы KION 2021 года.
Статические метаданные считаются доступными; журнал показов и все реальные
переходы пользователя в данных отсутствуют. Сравнивать абсолютный NDCG между
разными candidate protocols и заданиями нельзя.
